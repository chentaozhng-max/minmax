# PsyMatch

**当前版本：v1.3**

心理学实验的报名与排期平台。主试发布实验和可约时段，被试挑一个时段报名，
然后走两段式确认、现场签到、信誉分结算。移动端优先（375×812 起），界面全中文。

> **给 AI / 接手的同学**：先读 [AGENTS.md](./AGENTS.md)——启动命令、演示账号、硬性约束、
> 目录地图、分层判据、故障排查表都在那。要改结构再读 [ARCHITECTURE.md](./ARCHITECTURE.md)。
> 本文只讲产品：它解决什么问题、怎么用、做到什么程度。

## 一个场景

陈砚是心理系博士生，要招 30 个人做「面孔吸引力判断实验」，每人 30 分钟，给 ¥30。

- **发布**：填标题 / 简介 / 时长 / 奖励 / 报名门槛，勾几个时段，发出去。
  时段可以批量追加（按天 × 时间段 × 每段时长自动切，全部对齐到整点半点）。
- **被试找过来**：首页卡片流，可以按「今天 / 明天 / 时长 / 是否够资格」筛。
  主试信誉低于 60 的实验排最后并打灰标——先让人看到可信的。
- **被试报名**：挑一个时段 → 提交 → 等主试确认 → 确认后进「我的预约」。
  距开始不足 12 小时不能取消（提示去签到），避免最后时刻把名额占死。
- **现场**：被试点「到场签到」→ 主试点「确认到场」→ 双方信誉 +1。
- **出岔子**：被试没来 → 主试标未到 → 被试 -2 并进禁期（1/1/1/7/7 天阶梯）。
  被试觉得冤枉 → 提申诉 → 主试 48 小时不回应自动判成立并结算主试。

全程不需要打电话、微信群接龙或 Excel。

## 助手能做什么

被试端有一个对话入口：

- **门厅**（`/assistant/chat`，跨实验）：「周三下午有空，别太久，奖励高一点的」
  → 它把这句话拆成条件（周三 / 下午 / ≤60 分钟 / 按奖励排），从全部实验里筛出候选卡片。
  被筛掉的会告诉你为什么（比如「门槛要求信誉 80，你当前 72」）。
- **房间**（`/experiments/[id]/chat`，单实验）：在这门实验的时段里帮你挑 2–3 个候选，
  点「就这个」直接锁定。

**没配 API key 也能用**：自动降级——门厅直接搜一次给列表，房间换成时段多选表单。
所有预约路径最终都走同一个 `bookSlot()`，校验一模一样。

助手不做的事：不用它改实验、不跨实验直接下单、不替你做「多门实验时间网格」这种推理。
点候选卡片会跳回对应实验的房间页完成预约。

## 3 分钟跑起来

```bash
npm install
npm run setup     # 生成 Prisma Client + 建库 + 灌种子
npm run dev       # http://localhost:3000
```

不用手动建 `.env`：`setup` / `dev` / `build` / `start` 前面都会按 `.env.example` 补一份。

**Windows 最省事**：双击根目录的 `启动 PsyMatch.cmd`，它会依次检查 Node / 端口 / 依赖 /
`.env` / 数据库 / 构建产物，就绪后自动开浏览器。那个窗口就是服务器，关掉就停。

国内网络慢可以加镜像：`npm install --registry=https://registry.npmmirror.com`

## 演示路径（评委版）

1. `13900000001` 登录 → 首页卡片流（含「主试信誉较低」灰标那条在最后）
2. 点「面孔吸引力判断实验」→ 详情页 → 「立即预约」→ 选一个时段
3. 去 `/assistant/chat` 说「周三下午有空，别太久，奖励高一点的」→ 看它拆条件 + 给卡片 + 说清筛掉了谁
4. 点卡片回到实验房间 → 助手给候选 → 「就这个」→ 预约成立
5. 「我的预约」→ 确认 → 「到场签到」
6. 换 `13800000001` 登录 → 底部凸起的「+」发布实验；「我的实验」→ 确认到场 → 双方信誉 +1
7. 主试端有林知夏的待处理申诉，可现场演示「驳回 / 认了」

## 做到什么程度

```
54 个测试文件 / 591 用例      npm test             纯逻辑 + 适配器 + 页面查询，全绿
62 项数据库级验收            npm run accept       防超卖 / 禁期阶梯 / 取消结算 / 签到 / 申诉超时
197 个文件分层检查           npm run lint:layers  L1–L7 硬红线 + 棘轮
26 个页面 / 34 个 API 路由
真模型端到端已验证           门厅搜索 1.9s、5 个条件全抽对、多轮指代延续正确
```

关键机制都验过：

- **防超卖**：同容量 1 时段两个并发只成功 1 个，靠条件 UPDATE 在同一事务里做（不是先查后改）
- **主试取消的 24 小时线是逐条的**：同一场实验里 48h 后那场不扣分、2h 后那场扣分，结果并存
- **禁期阶梯**：第 1/2/3 次各 1 天，第 4 次起 7 天，只延长不缩短
- **申诉超时**：48 小时无回应自动成立，主试 -2
- **降级**：清空 `LLM_API_KEY` 重启，门厅和房间都自动换表单，功能完整

## 技术概要

Next.js 15 单体 + Prisma + SQLite（本地），服务端按**领域层 / 应用层 / 适配层**分层：

```
src/domain/        规则、状态机、纯函数、端口定义（零外部依赖）
src/application/   用例：编排领域概念 + 调端口
src/adapters/      Prisma 实现、LLM 调用（唯一碰外部世界的地方）
src/app/           页面与 API（薄壳）
src/tools/         Agent 工具（房间 7 个 / 门厅 1 个）
```

换数据库、换 LLM、换通知渠道只加一个适配实现，领域层一个字不改。
分层由 `scripts/check-layers.mjs` 强制，详见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

**部署到服务器**：`schema.prisma` 的 `provider` 改 `postgresql` + 换 `DATABASE_URL`，
`npx prisma db push && npm run build && npm start`。字段/索引/唯一约束/防超卖 SQL 全通用。
